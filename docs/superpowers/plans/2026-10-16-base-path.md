# Comunicado Semanal em `/boletim_ti/` (BASE_PATH) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer o sistema funcionar integralmente na raiz e em `/boletim_ti/` (variável `BASE_PATH`), com Apache2 como proxy reverso, Docker reconstruído e dependências sem alertas do `npm audit`.

**Architecture:** Um módulo central (`src/base-path.js`) normaliza `BASE_PATH` e monta URLs; o Express monta todas as rotas num `Router` sob o prefixo; templates e JS do navegador usam o helper (`u()` / `Api.url`); sessão com cookie próprio e `Path` do prefixo. Apache repassa o prefixo sem retirá-lo. Docker e dependências ajustados por arquivos/versões, sem aplicar nada em produção.

**Tech Stack:** Node.js ≥ 22.12, Express 5, EJS, mysql2, express-session + express-mysql-session, puppeteer-core 25, node:test + supertest, MariaDB de teste em `127.0.0.1:3307`.

**Spec:** `docs/superpowers/specs/2026-10-16-base-path-design.md`

## Global Constraints
- `BASE_PATH` ausente/vazio/`/` = modo raiz (comportamento atual preservado). Formato aceito: `^/[A-Za-z0-9._~-]+(/[A-Za-z0-9._~-]+)*$` após `trim` e remoção de barras finais; rejeitar `//`, `..`, `http://`, `?`, `#`, `\`, `%`, espaços.
- Nada fora do prefixo é servido (404), exceto `/saude` na raiz (healthcheck Docker) e `base + '/saude'`.
- Cookie de sessão: nome `boletim.sid`, `Path = base || '/'`, `HttpOnly`, `SameSite=Lax`, `Secure` por `COOKIE_SECURE` (só `false` quando sem HTTPS). CSRF, bcrypt, bloqueio de login e demais proteções inalterados.
- Redirects só para destinos constantes internos via `u()`; nunca destino vindo do usuário.
- Contratos das APIs e cabeçalhos preservados (`X-Ajuste`, `X-Falta-Mm`, `X-CSRF-Token`, corpos 401/403/409 em JSON, `saveToken`).
- Sem substituição global cega de strings; revisão ponto a ponto. Sem novas dependências (exceto a atualização do `puppeteer-core`).
- Cada arquivo de teste que usa o banco define seu próprio `process.env.BOLETIM_TEST_DB` (prefixo `boletim_test`). `npm test` = `node --env-file=.env.test --test "tests/**/*.test.js"`; os 201 testes existentes continuam passando.
- Nunca `npm audit fix --force`. Nenhum segredo em arquivos/logs/commits. Não alterar banco de produção, outros serviços ou VirtualHosts automaticamente.
- Faixa de rede do Apache: marcador explícito `FAIXA_AUTORIZADA_AQUI` (a configuração deve falhar no `configtest` até o usuário preencher).
- Commits no branch `feat/base-path`; mensagens terminam com `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus
1. `BASE_PATH` malicioso/malformado (`//evil.com`, `/a/../b`, `http://x`, `/a?b`, `/a b`, `/%2e%2e`) → rejeitado na subida com mensagem clara; nunca vira redirect para fora.
2. Cookies de outras aplicações no mesmo host (`sid`, `PHPSESSID`) não afetam nem são afetados; `Path` não vaza para `/boletim_tiXYZ`.
3. Requisição fora do prefixo (`/login`, `/api/configuracoes`, `/edicoes/1`) no modo prefixado → 404 sem sessão; `/boletim_ti` sem barra final e `/boletim_ti//login` tratados sem erro 500.
4. Link/form/script/fetch esquecido com caminho absoluto → pego pelo teste de varredura (templates e JS), não só pelo olho.
5. Downloads, logo (`<img>` e upload raw), pré-visualização (`srcdoc`) e salvamento automático funcionando sob o prefixo; mensagens de erro (403/404/500) com links corretos.
